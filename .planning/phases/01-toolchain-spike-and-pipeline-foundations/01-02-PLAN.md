## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub/Geofabrik to data_dir | untrusted downloads |
| zip archive to filesystem | untrusted member paths |
| PyPI to KnoxMap venv | third-party packages that execute during every build |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Tampering | zip extraction (zip slip) | high | mitigate | safe_extract validates every member path, requires fresh empty dest, tested |
| T-01-05 | Tampering | OSM extract (Geofabrik publishes MD5 from same server) | medium | mitigate | own SHA-256 recorded at first download (TOFU) and re-verified every build |
| T-01-06 | Tampering | tools/CLI/KnoxMap binaries; KnoxMap Setup fetches tools unhashed | high | mitigate | pins verify hashes zips, CLI exe and tree manifest before any run; fail closed |
| T-01-07 | Elevation | executing downloaded code | high | mitigate | no extracted binary executed in Tasks 1 and 2; Task 3 resolves with --only-binary and --dry-run (no code run) and installs with --require-hashes --no-deps; later runs use explicit paths, not cwd inside the tree |
| T-01-32 | Tampering | silent tools switch to 260909 | medium | mitigate | verify fails when fallback status is active or a switch lacks `[tools.active.approval]` with date, reason, existing evidence file |
| T-01-SC | Tampering | pip installs executed during a build (KnoxMap venv, transitive set) | high | mitigate | implemented by Task 3: wheels-only resolution, per-package human review (blocking-human, never auto-approved), `--require-hashes` install, list+hash+site-packages manifest recorded in PINS and checked by `pa pins verify` (Task 1 Test 7); project venv deps stay pinned by requirements.lock hash |
