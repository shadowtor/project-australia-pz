Command in build.log: `PZWorldEd_cli.exe --generate-map=...\pa_spike_melb.pzw --cells=0,0,0,0` (via KnoxMap
`compile_map`, backend worlded). The CLI hung 30 minutes ("batch 1/1 hung - no end after 30 minutes, stopped"),
twice (retry too); I killed the retry.

Tool log (`tools/settings/logs/PZWorldEd-*.log`, last lines):
```
Application Build 20260909f
Opening PZTools Initial Setup: configuration valid= true Tiles valid= false
```

`Tiles/2x/*.png` sheets exist. KnoxMap Setup normally does this (configure_tools in knoxmap_setup.py): writes
PZTools.ini (TilesDirectory, ProjectZomboidDirectory), extracts ~540 tile sheets from the game's texturepacks with
`tools/extract_tiles.py`, prunes Tilesets.txt, and patches Rules.txt (kerbs/road/tree rules). Plan 01-02 locked
the venv but not this step, and "KnoxMap Setup is never invoked" in this plan, so it was not run.
Not yet observed: whether the 261030 tools then compile one cell (CLI exit code, world_X_Y.lotpack, X_Y.lotheader,
chunkdata_X_Y.bin, Qt/DLL/version warnings). 261030 also bundles the same Qt5 DLLs; no Qt/DLL load error occurred.
